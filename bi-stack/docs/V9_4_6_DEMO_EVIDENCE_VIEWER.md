# V9.4.6 — Demo Evidence Viewer in UI

## Goal

V9.4.6 adds a UI-level viewer for the latest successful or failed dual-path demonstration run generated by `V9.4.5a — Dual-Path Validation Isolation Fix`.

It does not replace the live validation script. It makes its outputs visible from the MCAD BI dashboard so that the demonstrator can be shown without switching to the terminal.

## What is displayed

The new **Demo Validation** tab displays:

- latest run id;
- PASS/FAIL status;
- passed steps / total steps;
- generation timestamp;
- run directory;
- validation-step table;
- execution path and adapter;
- physical execution flag;
- response digest;
- XMLA response type;
- Markdown preview.

It also provides buttons to open:

- `dual_path_summary.md`;
- `dual_path_steps.csv`;
- `dual_path_summary.json`.

## Backend endpoints

V9.4.6 adds:

```text
GET /mcad/demo-evidence/runs
GET /mcad/demo-evidence/latest
GET /mcad/demo-evidence/runs/{run_id}
GET /mcad/demo-evidence/latest/markdown
GET /mcad/demo-evidence/latest/csv
GET /mcad/demo-evidence/latest/json
GET /mcad/demo-evidence/runs/{run_id}/markdown
GET /mcad/demo-evidence/runs/{run_id}/csv
GET /mcad/demo-evidence/runs/{run_id}/json
```

## Docker requirement

The proxy needs access to the host-side evidence directory generated by the validation script. Therefore `docker-compose.yml` mounts:

```yaml
./demo-evidence:/app/demo-evidence:rw
```

and sets:

```yaml
MCAD_DEMO_EVIDENCE_DIR: /app/demo-evidence
```

## Usage

1. Run the dual-path validation pack:

```bash
bash bi-stack/scripts/run_dual_path_demo_validation.sh .
```

2. Rebuild/restart the proxy if V9.4.6 has just been applied:

```bash
docker compose -f bi-stack/docker-compose.yml build --no-cache mcad-proxy
docker compose -f bi-stack/docker-compose.yml up -d mcad-proxy
```

3. Open:

```text
http://127.0.0.1:9000/mcad/session/ui
```

4. Click **Demo Validation**.

## Validation

Run:

```bash
bash bi-stack/scripts/check_demo_evidence_viewer.sh .
```

Expected:

```text
Summary: fails=0
```

If no demo evidence run exists yet, the check may report a warning about `latest_path.txt`; run the V9.4.5a validation script first.
